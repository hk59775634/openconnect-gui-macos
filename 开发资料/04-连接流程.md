# 04 — 连接流程

## 1. 端到端流程

```
用户选择节点
      │
      ▼
① 准备参数
   gateway = HostAddress
   user / password = 本地凭证
      │
      ▼
② 协议库初始化
   vpninfo_new
   set_protocol("anyconnect")
   parse_url(gateway)
      │
      ▼
③ 身份认证
   obtain_cookie（填写用户名/密码表单，必要时 MFA）
      │
      ▼
④ 建立数据通道
   make_cstp_connection   ← TLS/TCP（CSTP）
   setup_dtls（可选）      ← UDP 加速，失败可忽略
      │
      ▼
⑤ 创建虚拟网卡
   setup_tun_device / 平台等价 API
   配置 IP、DNS、路由（由库 + vpnc-script / 系统 API 完成）
      │
      ▼
⑥ 主循环
   mainloop 收发隧道数据
      │
      ▼
已连接 —— 用户可上网 / 访问内网资源
      │
      ▼
⑦ 断开
   停止 mainloop → 拆除 TUN → 释放会话
```

**判定「已连接」**：认证成功 + CSTP 成功 + TUN 就绪 + 主循环已启动。  
仅拿到 cookie 不应对用户显示为已连接。

## 2. 阶段说明

### ② 初始化

- User-Agent 可自定义（便于服务端识别客户端）。
- 协议名固定为 `anyconnect`（除非服务方另行通知）。

### ③ 认证

- 库通过认证表单回调索要字段：常见为 username、password；可能有 authgroup、token。
- 账号密码错误时 `obtain_cookie` 失败，需向用户展示明确错误。

### ④ CSTP / DTLS

| 通道 | 作用 |
|------|------|
| CSTP | 必选，TLS over TCP |
| DTLS | 可选加速；失败自动回退，连接仍可用 |

### ⑤ TUN

| 平台 | 常见依赖 |
|------|----------|
| Windows | Wintun 或 TAP-Windows；通常需**管理员权限** |
| Android | `VpnService` 授权 |
| iOS | Network Extension / Packet Tunnel |
| Linux / macOS | tun 设备权限 |

### ⑥ 路由与 DNS

连接后网关可能下发：

- 隧道 IP / 掩码 / 网关
- DNS 服务器
- 全隧道或分流路由

自研 APP 需决定：

- **全局模式**：默认路由进隧道
- **分流模式**：仅部分流量进隧道（实现复杂，可二期）

## 3. 断开与重连

| 动作 | 要求 |
|------|------|
| 用户断开 | 干净停止 mainloop、释放网卡与路由，可再次连接 |
| 网络闪断 | 可选自动重连（使用上次三要素）；注意避免重复 TUN |
| 切换节点 | 先断开再连新 `HostAddress` |

## 4. 证书策略（建议）

| 策略 | 适用 |
|------|------|
| 系统信任链校验 | 正式环境默认 |
| 证书指纹 Pin | 高安全或固定网关 |
| 允许不安全证书 | **仅开发联调**，正式包勿默认开启 |

## 5. 日志建议

便于排障，建议记录（**勿记录密码明文**）：

- profile 下载 URL 与结果（节点数量）
- 连接目标 HostAddress（可脱敏）
- 认证 / CSTP / TUN / mainloop 各阶段成功或错误码
- DTLS 是否启用
